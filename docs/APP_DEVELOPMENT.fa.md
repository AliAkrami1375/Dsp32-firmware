# ساخت اپلیکیشن برای Dsp32

[English](APP_DEVELOPMENT.md) · **فارسی**

هر چیزی که برای نوشتن، بسته‌بندی، نصب و انتشار نرم‌افزار روی یک دستگاه Dsp32
لازم دارید.

---

## ۱. Dsp32 چیست

Dsp32 فرمویری است که یک ESP32 را به کامپیوتر مستقل تبدیل می‌کند. برد هات‌اسپات
وای‌فای خودش را بالا می‌آورد و یک دسکتاپ کامل را روی HTTP به هر دستگاهی که وصل
شود تحویل می‌دهد — گوشی، تبلت یا لپ‌تاپ. هیچ چیزی روی دستگاه کاربر نصب نمی‌شود
و اینترنت لازم نیست.

سه واقعیت همه‌چیز را درباره‌ی نوشتن اپ برایش تعیین می‌کند.

**دسکتاپ در مرورگر اجرا می‌شود؛ دستگاه بک‌اند است.** اپ شما جاوااسکریپتی است که
روی مرورگر کاربر اجرا می‌شود. وقتی به سخت‌افزار نیاز دارد — فایل، پین، دوربین،
شبکه — دستگاه را با REST صدا می‌زند. همین تقسیم کار است که باعث می‌شود یک اپ
چند کیلوبایتی کار واقعی انجام دهد.

**دستگاه کوچک است.** یک ESP32 موقع سرو کردن دسکتاپ حدود ۱۰۰ کیلوبایت heap آزاد
دارد. فرمویر هیچ‌وقت بسته را باز نمی‌کند؛ فقط بایت ذخیره می‌کند. تمام باز کردن
بسته در مرورگر انجام می‌شود.

**اپ‌ها داخل فرمویر نیستند.** ایمیج خودِ سیستم‌عامل را جا می‌دهد — ۹۲ کیلوبایت
فشرده، که ۴۰ کیلوبایتش اپ‌های داخلی است — و هیچ چیز دیگر. هر چیز قابل نصبی در
یک رجیستری زندگی می‌کند و فقط وقتی لازم شود دانلود می‌شود.

</div>

```
ایمیج فرمویر (ESP32، فشرده)
  هسته‌ی سیستم‌عامل   ۳۶ KB   شل، مدیر پنجره، پلتفرم، نشست، نصب‌کننده
  اپ‌های داخلی        ۴۰ KB   فایل منیجر، ترمینال، تنظیمات، تسک منیجر و…
  تم و HTML           ۱۱ KB
  لوگو                 ۴ KB
  ───────────────────────────
  مجموع               ۹۲ KB   جاسازی‌شده

اپ‌های قابل نصب        ۰ KB   وقتی کاربر بخواهد از رجیستری دانلود می‌شوند
```

## ۲. ابزار توسعه

`tools/dsp32` تنها ابزاری است که لازم دارید. هیچ وابستگی‌ای جز پایتون ۳.۸
ندارد و یک فایل واحد است، پس هر جایی قابل کپی کردن است.

</div>

```bash
# اختیاری: روی PATH بگذاریدش
export PATH="$PATH:/path/to/Dsp32/tools"

dsp32 --help
```

<div dir="rtl">

| دستور | چه کار می‌کند |
|---|---|
| `dsp32 new <name>` | اسکلت اپی می‌سازد که همان‌طور که هست بیلد و اجرا می‌شود |
| `dsp32 build [dir]` | اعتبارسنجی و کامپایل به یک بسته‌ی `.dib` |
| `dsp32 check [dir\|file]` | لینت سورس، یا بررسی یک بسته‌ی ساخته‌شده |
| `dsp32 watch [dir]` | با هر ذخیره دوباره بیلد می‌کند و اختیاری روی دستگاه می‌فرستد |
| `dsp32 install [dir] --to <host>` | بیلد و ارسال مستقیم روی برد |
| `dsp32 registry <dirs…> --base <url>` | بازسازی ایندکس رجیستری |
| `dsp32 doctor` | بررسی ابزارها و اینکه دستگاه جواب می‌دهد یا نه |

### شصت ثانیه، از صفر تا اجرا

</div>

```bash
dsp32 new weather --author "نام شما"
dsp32 install weather --to 10.3.2.1
```

<div dir="rtl">

دسکتاپ را رفرش کنید و اپ روی آن است. موقع توسعه:

</div>

```bash
dsp32 watch weather --to 10.3.2.1
```

<div dir="rtl">

هر ذخیره دوباره بیلد و ارسال می‌کند؛ مرورگر را رفرش کنید تا تغییر را ببینید.

```
  weather.dib    بسته‌ی ساخته‌شده
```

<div dir="rtl">

### مانیفست

</div>

```json
{
  "id": "ir.dibachain.weather",
  "name": "Weather",
  "version": "1.0.0",
  "author": "نام شما",
  "description": "قبل از نصب در فروشگاه نشان داده می‌شود.",
  "entry": "main.js",
  "styles": ["style.css"],
  "icon": "icon.svg",
  "permissions": ["storage", "notify", "system"],
  "minFirmware": "1.0.0"
}
```

<div dir="rtl">

| فیلد | اجباری | توضیح |
|---|---|---|
| `id` | ✅ | روی دستگاه نام پوشه می‌شود، پس `[a-z0-9._-]` و ۲ تا ۴۸ کاراکتر. reverse-DNS از تداخل جلوگیری می‌کند: `ir.dibachain.weather` |
| `name` | ✅ | روی دسکتاپ، منوی استارت و تسک‌بار دیده می‌شود |
| `version` | ✅ | عددی، مثل `1.2.3`. فروشگاه با آن به‌روزرسانی را تشخیص می‌دهد |
| `entry` | ✅ | فایل جاوااسکریپتی که اجرا می‌شود |
| `styles` | | فایل‌های CSS که پیش از اجرای entry به صفحه تزریق می‌شوند |
| `icon` | | یک SVG داخل بسته. بدون آن اپ آیکون عمومی می‌گیرد |
| `permissions` | | چیزی که اپ اجازه دارد به آن برسد — پایین‌تر |
| `description` و `author` | | قبل از نصب نشان داده می‌شوند. بنویسیدشان |
| `minFirmware` | | روی فرمویر قدیمی‌تر نصب نمی‌شود |

فیلدهای `files` و `payloadSha256` و `payloadSize` و `compression` را خودِ
`build` پر می‌کند. دستی ننویسیدشان.

### استایل‌ها

هر چیزی بیشتر از چند قاعده، جایش یک فایل `.css` واقعی است نه یک رشته‌ی
قالبی داخل جاوااسکریپت. آن را زیر `styles` فهرست کنید تا لودر پیش از اجرای
فایل entry تزریقش کند؛ اینطوری پنجره از همان فریم اول استایل‌خورده کشیده
می‌شود:

<div dir="ltr">

```json
"styles": ["style.css", "theme.css"]
```

</div>

قاعده‌ها در همان استایل‌شیت سراسری دسکتاپ می‌نشینند، پس به هر سلکتور یک
پیشوند مخصوص اپ بدهید. `.wx-row` امن است، `.row` دیر یا زود با اپ دیگری
درگیر می‌شود.

### فایل entry

</div>

```js
Dsp32.app(function (App) {
  const win = App.window({ title: 'Weather', w: 480, h: 360 });
  win.body.innerHTML = '<div style="padding:20px">Hello</div>';
  return win;
});
```

<div dir="rtl">

`Dsp32.app(fn)` اپ را ثبت می‌کند. تابع `fn` **هر بار که اپ اجرا شود** صدا زده
می‌شود و یک شیء `App` می‌گیرد که به مجوزهای مانیفست محدود شده است. هر چه
برگرداند به‌عنوان پنجره در نظر گرفته می‌شود.

هر چیزی که CSS خود دسکتاپ فراهم می‌کند در اختیار شماست: `.btn` و
`.btn.primary` و `.tinput` و `.switch` و `.meter` و `.empty-state`، و
متغیرهای `--accent` و `--text` و `--text-2` و `--card` و `--stroke` و
`--mono`. استفاده از اینها یعنی اپ شما رایگان از تم و رنگ انتخابی کاربر
پیروی می‌کند.

## ۴. مجوزها

اپ اعلام می‌کند به چه چیزی نیاز دارد؛ فروشگاه آن لیست را قبل از نصب نشان
می‌دهد؛ runtime آن را اعمال می‌کند. صدا زدن متدی که مانیفست اعلامش نکرده
بلافاصله خطا می‌دهد — پس مجوز فراموش‌شده موقع توسعه معلوم می‌شود نه اینکه
بعداً در میدان بی‌صدا کار نکند.

| مجوز | چه می‌دهد |
|---|---|
| `storage` | `App.storage` — فضای کلید/مقدار خصوصی |
| `fs` | `App.fs` — خواندن و نوشتن زیر `/flash` و `/sd` |
| `net` | `App.net` — درخواست HTTP(S) از طریق دستگاه |
| `notify` | `App.notify()` — اعلان دسکتاپ |
| `system` | `App.system()` — چیپ، حافظه، سنسورها |
| `camera` | `App.camera` — عکس و ذخیره |

دستور `dsp32 build` مانیفست و کد را **دوطرفه** مقایسه می‌کند: استفاده از چیزی
که اعلام نکرده‌اید خطاست، و اعلام چیزی که هرگز استفاده نمی‌کنید هشدار — چون
هر مجوزی که فهرست کنید به کاربر نشان داده می‌شود، و لیست صادقانه لیست
کوتاه‌تر است.

> **این یک sandbox امنیتی نیست.** اپ نصب‌شده جاوااسکریپتی روی همان صفحه‌ی
> دسکتاپ است و به هر چیزی که دسکتاپ دسترسی دارد می‌رسد، چه اعلام کرده باشد چه
> نه. لیست مجوزها می‌گوید یک اپ **صادق** قصد دارد از چه چیزی استفاده کند.
> ایزوله‌سازی واقعی نیاز دارد هر اپ در iframe مخصوص خودش باشد که نسخه‌ی فعلی
> این کار را نمی‌کند. فقط بسته‌هایی را نصب کنید که به منبعشان اعتماد دارید.

## ۵. رابط runtime

هر چیزی که پایین می‌آید روی شیء `App` است که تابع شما دریافت می‌کند.

### پنجره‌ها

</div>

```js
const win = App.window({ title: 'Weather', w: 480, h: 360, onClose: cleanup });
win.body.innerHTML = '…';        // محتوای شما
win.setTitle('Weather — Tehran');
win.close();
```

<div dir="rtl">

`App.window` همان شیئی را برمی‌گرداند که `WM.open` می‌دهد: `body` و
`setTitle` و `close` و `min` و `max` و `snapTo('left'|'right')` و `rect` و
`setRect` و `focus`.

برای بقا بعد از رفرش مرورگر، `win.session = () => ({ … })` بگذارید. هر چه
برگردانید دفعه‌ی بعد به‌عنوان `App.args` برمی‌گردد:

</div>

```js
Dsp32.app(function (App) {
  const restored = App.args || {};
  const win = App.window({ title: 'Weather' });
  let city = restored.city || 'Tehran';
  win.session = () => ({ city });
  …
});
```

<div dir="rtl">

### ذخیره‌سازی — `storage`

خصوصی برای اپ شما، ذخیره‌شده روی کلاینت.

</div>


### فایل‌سیستم — `fs`

</div>

```js
const { entries } = await App.fs.list('/flash/Documents');
const text = await App.fs.read('/flash/Documents/notes.txt');
await App.fs.write('/flash/Documents/notes.txt', 'hello');
```

رفرش شود.

### شبکه — `net`

دسکتاپ از `10.3.2.1` سرو می‌شود، پس مرورگر نمی‌تواند به origin دیگری درخواست
بزند. `App.net` از طریق دستگاه می‌رود که اتصال بالادست دارد.

</div>

```js
const data = await App.net.json('https://api.example.com/weather?q=Tehran');
const text = await App.net.text('https://example.com/robots.txt');
const res  = await App.net.fetch('https://example.com/file.bin');

// POST همراه با بدنه
const out = await App.net.fetch(url, {
  method: 'POST',
  body: JSON.stringify({ phone: '+98912…' }),
});
```

<div dir="rtl">

دستگاه بدنه را در قطعات ۲ کیلوبایتی عبور می‌دهد و پاسخ بالای ۱ مگابایت را رد
می‌کند. به اتصال وای‌فای بالادست نیاز دارد — تنظیمات ← شبکه، یا آیکون وای‌فای
در تسک‌بار.

پاسخ ۴xx یا ۵xx از سرور مقابل **خطا پرتاب می‌کند** و متن خطا همان چیزی است که
خود سرور گفته — `error`، `message` یا `detail` از بدنه‌ی JSON، و اگر کوتاه بود
خود متن خام. تقریباً همیشه همین را می‌خواهید نشان بدهید: «کد اشتباه است» خیلی
بهتر از «HTTP 400» است. اگر لازم شد روی کد وضعیت شرط بگذارید، `err.status`
همان کد سرور مقابل را دارد.

</div>

```js
try {
  await App.net.fetch(bridge + '/auth/verify', { method: 'POST', body });
} catch (e) {
  if (e.status === 400) showError(e.message);   // → «کد اشتباه است»
}
```

<div dir="rtl">

چون پراکسی جریانی است، خط وضعیت خودش پیش از آنکه وضعیت سرور مقابل معلوم شود
قطعی شده — بنابراین وضعیت سرور مقابل در هدر `X-Dsp32-Status` برمی‌گردد و
`App.net.fetch` خودش آن را می‌خواند.

## ۶. قالب بسته‌ی `.dib`

یک `.dib` تک فایلی است که مانیفست و همه‌ی دارایی‌ها را دارد.

</div>

```
┌────────┬──────────────┬───────────────────┬──────────────────────┐
│ "DIB1" │ manifestLen  │  manifest (JSON)  │  payload             │
│ ۴ بایت │ ۴ بایت u32 LE│  manifestLen بایت │  فایل‌های چسبیده      │
└────────┴──────────────┴───────────────────┴──────────────────────┘
                                             └── اختیاری: gzip شده ┘
```

<div dir="rtl">

little-endian، بدون padding. خواننده بعد از ۱۲ بایت همه‌چیز را درباره‌ی بقیه‌ی
فایل می‌داند.

آرایه‌ی `files` در مانیفست `path` و `offset` و `size` را داخل payload
**بازشده** می‌دهد، پس خواننده یک بار فشرده‌سازی را باز می‌کند و بعد برش
می‌زند. `payloadSha256` payload بازشده را پوشش می‌دهد و موقع نصب بررسی
می‌شود.

صحت با یک SHA-256 که در جاوااسکریپت خالص پیاده شده بررسی می‌شود نه با
`crypto.subtle`، چون `http://10.3.2.1` یک secure context نیست و مرورگرها
WebCrypto را آنجا نمی‌دهند. این خرابی و دانلود ناقص را تشخیص می‌دهد.
**امضا نیست** و اثبات نمی‌کند بسته را چه کسی ساخته.

مشخصات کامل: [DIB_FORMAT.fa.md](DIB_FORMAT.fa.md)

## ۷. نصب

چهار مسیر به دستگاه می‌رسد:

| مسیر | چه وقت |
|---|---|
| `dsp32 install --to <host>` | موقع توسعه. سریع‌ترین چرخه |
| فروشگاه ← Install ← از فایل | وقتی یک `.dib` را با کسی به اشتراک می‌گذارید |
| فروشگاه ← Install ← از URL | وقتی خودتان بسته را میزبانی می‌کنید |
| فروشگاه ← Browse | انتشار از طریق رجیستری |

دسکتاپ بسته را در `/flash/Apps/<id>/` باز می‌کند و یک `.dib.json` کنار
فایل‌هایتان می‌نویسد. موقع راه‌اندازی، دسکتاپ `/flash/Apps` و `/sd/Apps` را
اسکن می‌کند، هر مانیفست را می‌خواند و هر فایل entry را اجرا می‌کند — **پس اپ
تازه‌نصب‌شده فقط بعد از رفرش ظاهر می‌شود.**

فایل‌های `.js` تنها که مستقیم در `/flash/Apps` بگذارید هنوز به‌عنوان اپ
تک‌فایلی بدون مانیفست کار می‌کنند. آنها کل پلتفرم را مستقیم می‌گیرند —
`Shell` و `WM` و `API` و `I` — بدون محدودیت مجوز. برای یک آزمایش سریع خوب
است؛ برای هر چیزی که به اشتراک می‌گذارید از بسته استفاده کنید.

چون `/sd/Apps` هم اسکن می‌شود، می‌توانید با نوشتن فایل روی کارت حافظه‌ی یک
برد Dsp32 برایش نرم‌افزار بنویسید.

---

## ۸. انتشار

رجیستری یک ایندکس JSON است. هر میزبان استاتیکی سرو می‌کند — یک آدرس raw از
گیت‌هاب، یک باکت S3، یا فایلی روی کارت SD خود دستگاه.

</div>

```bash
dsp32 build weather
dsp32 registry . --base https://raw.githubusercontent.com/you/apps/main -o registry.json
```

<div dir="rtl">

`sha256` کل فایل `.dib` را پوشش می‌دهد، پس فروشگاه دانلود را قبل از باز کردن
بررسی می‌کند. کاربران آدرس رجیستری شما را در بخش **Browse** فروشگاه وارد
می‌کنند.

هر بار بسته‌ای عوض شد ایندکس را دوباره بسازید — checksum کهنه یک دانلود
کاملاً سالم را رد می‌کند، و این دقیقاً همان چیزی است که باید خودکار شود نه
دستی.

## ۹. قراردادها

**کوچک نگهش دارید.** کل دسکتاپ ۹۲ کیلوبایت فشرده است. اپی که از سیستم‌عامل
بزرگ‌تر باشد کار اشتباهی می‌کند. بدون فریم‌ورک — پلتفرم پنجره و دیالوگ و
انتخابگر فایل و تم را از قبل داده.

**از تم استفاده کنید.** رنگ هاردکد لحظه‌ای که کسی به تم روشن برود یا رنگ
دیگری انتخاب کند غلط به نظر می‌رسد. از متغیرهای CSS استفاده کنید.

**CSS خود را محدود کنید.** بسته نمی‌تواند stylesheet اضافه کند، پس یک
`<style>` داخل body پنجره‌تان تزریق کنید و هر قانون را زیر یک کلاس مخصوص
خودتان ببرید. `Diba Manager` همین کار را می‌کند؛ الگویش را کپی کنید.

**موقع بسته شدن تمیز کنید.** `win.onClose` بگذارید و intervalهایتان را پاک
کنید. تایمر نشتی بعد از بسته شدن پنجره هم دستگاه را می‌کوبد.

**آرام poll کنید.** هر درخواست وقت واقعی دستگاه را می‌گیرد. یک درخواست ترکیبی
در ثانیه از ده درخواست کوچک بهتر است، و هیچ چیز نباید وقتی پنجره‌اش بسته است
poll کند.

**بلند شکست بخورید.** اگر دستگاه نه گفت، به کاربر نشان دهید چه گفت. بلاک
catch ساکت یک اصلاح پنج‌ثانیه‌ای را به یک بعدازظهر تبدیل می‌کند.

## ۱۰. رفع اشکال

**اپ بعد از نصب ظاهر نمی‌شود.** اپ‌ها موقع راه‌اندازی ثبت می‌شوند — مرورگر را
رفرش کنید. اگر باز هم نبود، فروشگاه ← Installed را برای خطای بارگذاری ببینید.

**«tried to use X but its manifest does not declare that permission».**
دقیقاً همان چیزی که می‌گوید. آن را به `permissions` در `dib.json` اضافه کنید
و دوباره بیلد بگیرید. `dsp32 build` این را قبل از نصب می‌گیرد.

**`dsp32 install` به دستگاه نمی‌رسد.** مطمئن شوید روی هات‌اسپات برد هستید و
`dsp32 doctor --to <address>` بزنید. پیش‌فرض `10.3.2.1` است.

**`App.net` با «fetch failed» شکست می‌خورد.** دستگاه به اتصال وای‌فای خودش
نیاز دارد — هات‌اسپات به‌تنهایی اینترنت نیست. در تنظیمات ← شبکه وصلش کنید.

**بسته در بررسی صحت رد می‌شود.** دانلود خراب است یا دستکاری شده. دوباره بیلد
بگیرید، و اگر منتشر می‌کنید رجیستری را بازسازی کنید تا checksum بخواند.

**پین رزروشده.** فرمویر پین‌هایی که برای فلش، PSRAM، UART کنسول، دوربین یا SD
استفاده می‌کند را رد می‌کند. `/api/gpio/pins` می‌گوید کدام‌ها و چرا.
