# قالب بسته‌ی `.dib`

[English](DIB_FORMAT.md) · **فارسی**

یک فایل `.dib` معادل یک اپلیکیشن قابل نصب Dsp32 است: مانیفست، کد، آیکون و
دارایی‌ها در یک فایل واحد که می‌شود آن را به اشتراک گذاشت، دانلود کرد و نصب کرد.

## دو محدودیتی که این قالب را شکل داد

**دستگاه کوچک است.** یک ESP32 حدود ۱۰۰ کیلوبایت heap آزاد دارد. برای همین
فرمویر هیچ‌وقت بسته را باز نمی‌کند — فقط بایت‌ها را ذخیره می‌کند. باز کردن
بسته در مرورگر انجام می‌شود، جایی که دسکتاپ همین الان اجرا می‌شود و
`JSON` و `TextDecoder` و `DecompressionStream` رایگان در دسترس‌اند.

**آدرس `http://10.3.2.1` یک secure context نیست.** مرورگرها `crypto.subtle` را
فقط برای HTTPS و localhost فعال می‌کنند، پس WebCrypto در دسترس ما نیست. به
همین دلیل صحت بسته با یک SHA-256 خالص جاوااسکریپت بررسی می‌شود نه با API
پلتفرم. این کار خرابی و دانلود ناقص را تشخیص می‌دهد، اما امضا نیست و
اثبات نمی‌کند بسته را چه کسی ساخته.

## ساختار فایل

```
┌────────────┬──────────────┬───────────────────┬──────────────────────────┐
│  "DIB1"    │ manifestLen  │  manifest (JSON)  │  payload                 │
│  ۴ بایت    │ ۴ بایت LE    │  manifestLen بایت │  فایل‌های به‌هم‌چسبیده     │
└────────────┴──────────────┴───────────────────┴──────────────────────────┘
                                                 └── اختیاری: gzip شده ────┘
```

little-endian، بدون padding و بدون نیاز به هم‌ترازی. یک پارسر با خواندن
۱۲ بایت اول همه‌چیز را درباره‌ی بقیه‌ی فایل می‌داند.

## مانیفست

```json
{
  "format": 1,
  "id": "ir.dsp32.hello",
  "name": "Hello",
  "version": "1.0.0",
  "author": "Ali",
  "description": "اولین اپ Dsp32.",
  "entry": "main.js",
  "styles": ["style.css"],
  "icon": "icon.svg",
  "permissions": ["storage", "notify"],
  "compression": "gzip",
  "payloadSha256": "9f2c…",
  "payloadSize": 4096,
  "files": [
    { "path": "main.js", "offset": 0,    "size": 2310 },
    { "path": "icon.svg", "offset": 2310, "size": 640 }
  ]
}
```

| فیلد | اجباری | معنی |
|---|---|---|
| `format` | ✅ | نسخه‌ی قالب. الان `1`. |
| `id` | ✅ | شناسه به سبک reverse-DNS. همین نام پوشه‌ی نصب هم هست، پس باید برای فایل‌سیستم امن باشد: `[a-z0-9._-]` و حداکثر ۴۸ کاراکتر. |
| `name` | ✅ | چیزی که روی دسکتاپ و در منوی استارت دیده می‌شود. |
| `version` | ✅ | رشته‌ای شبیه semver. موقع به‌روزرسانی مقایسه می‌شود. |
| `entry` | ✅ | فایل جاوااسکریپتی که اجرا می‌شود، نسبت به ریشه‌ی بسته. |
| `styles` | | فایل‌های CSS داخل بسته که پیش از اجرای entry به صفحه تزریق می‌شوند. |
| `author`، `description` | | قبل از نصب در فروشگاه نشان داده می‌شوند. |
| `icon` | | یک SVG داخل بسته. اگر نباشد آیکون عمومی استفاده می‌شود. |
| `permissions` | | چیزی که اپ اعلام می‌کند لازم دارد — پایین‌تر توضیح داده شده. |
| `compression` | | `"none"` یا `"gzip"`، روی کل payload. |
| `payloadSha256` | | هش هگز payload **بعد از** باز شدن فشرده‌سازی. |
| `payloadSize` | | طول payload بازشده، برای یک بررسی ارزان. |
| `files` | ✅ | آفست‌ها داخل payload بازشده هستند. |
| `minFirmware` | | روی فرمویر قدیمی‌تر نصب نمی‌شود. |

چون `offset` و `size` به payload بازشده اشاره می‌کنند، خواننده یک بار
فشرده‌سازی را باز می‌کند و بعد فقط برش می‌زند — هرگز به ازای هر فایل
دوباره باز نمی‌کند.

## استایل‌ها

اپی که استایل کم ندارد نباید CSS را به شکل رشته داخل جاوااسکریپت بسازد.
فایل‌ها را زیر `styles` فهرست کنید؛ لودر هرکدام را می‌خواند، داخل یک تگ
`<style>` با کلیدی از شناسه‌ی اپ و مسیر فایل می‌گذارد و پیش از اجرای entry
به head سند اضافه می‌کند — یعنی همان اولین فریمی که اپ می‌کشد استایل‌خورده
است. تزریق دوباره‌ی یک فایل بی‌اثر است، و همین است که اجرای دوباره‌ی یک اپ
را ارزان می‌کند.

این استایل‌ها دقیقاً مثل استایل‌های خود دسکتاپ سراسری‌اند. هیچ scope ای در
کار نیست، پس به سلکتورهایتان پیشوند بدهید: کلاسی به نام `.row` با مال یکی
دیگر تداخل می‌کند. قرارداد اپ‌های همراه، یک پیشوند کوتاه به ازای هر اپ است —
`.sr-*` برای سروش و `.dm-*` برای دیبا منیجر.

## مجوزها

در مانیفست اعلام می‌شوند و قبل از نصب به کاربر نشان داده می‌شوند. تعیین
می‌کنند runtime چه چیزی به اپ بدهد، و وجودشان برای این است که کاربر با
اطلاع تصمیم بگیرد.

| مجوز | چه چیزی می‌دهد |
|---|---|
| `storage` | `App.storage` — یک فضای کلید/مقدار خصوصی، ذخیره‌شده روی دستگاه |
| `fs` | `App.fs` — خواندن و نوشتن هر جایی زیر `/flash` و `/sd` |
| `net` | `App.net.fetch()` — درخواست HTTP(S) از طریق دستگاه |
| `notify` | `App.notify()` — اعلان دسکتاپ |
| `system` | `App.system()` — اطلاعات چیپ، حافظه و جانبی‌ها |
| `camera` | `App.camera` — عکس گرفتن و ذخیره روی حافظه |

**اینها یک sandbox امنیتی نیستند.** اپ نصب‌شده به‌صورت جاوااسکریپت روی همان
صفحه‌ی دسکتاپ اجرا می‌شود، پس یک اپ خرابکار می‌تواند به هر چیزی که دسکتاپ
دسترسی دارد برسد، چه مجوزش را گرفته باشد چه نه. ایزوله‌سازی واقعی نیاز دارد
هر اپ در iframe مخصوص خودش اجرا شود که نسخه‌ی ۱ این کار را نمی‌کند. فقط
بسته‌هایی را نصب کنید که به منبعشان اعتماد دارید — لیست مجوزها می‌گوید یک اپ
**صادق** قصد دارد از چه چیزی استفاده کند، نه بیشتر.

## ساختار نصب‌شده روی دستگاه

نصب‌کننده بسته را داخل پوشه‌ی مخصوص خودش می‌نویسد:

```
/flash/Apps/
  ir.dsp32.hello/
    .dib.json      ← مانیفست، همان‌طور که نصب شد
    main.js
    icon.svg
    assets/…
```

موقع راه‌اندازی، دسکتاپ `/flash/Apps` و `/sd/Apps` را اسکن می‌کند، هر
`.dib.json` را می‌خواند و فایل entry را اجرا می‌کند. حذف نصب، کل پوشه را
پاک می‌کند.

فایل‌های `.js` تنها که مستقیم داخل `/flash/Apps` باشند هنوز کار می‌کنند —
به‌عنوان اپ تک‌فایلی بدون مانیفست در نظر گرفته می‌شوند.

## ساختن یک بسته

```bash
python3 tools/dibpack.py myapp/ -o myapp.dib
```

پوشه‌ی مبدأ باید یک `dib.json` داشته باشد با فیلدهایی که خودتان می‌نویسید —
`id`، `name`، `version`، `entry` و بقیه. ابزار خودش `files` و
`payloadSha256` و `payloadSize` و `compression` را پر می‌کند.

```
myapp/
  dib.json
  main.js
  icon.svg
```

برای دیدن محتوای یک بسته بدون نصب کردنش:

```bash
python3 tools/dibpack.py --info myapp.dib
```

## نصب کردن

سه راه، همه در اپ **App Store**:

- **از فایل** — یک `.dib` از کامپیوترتان انتخاب کنید؛ مرورگر بازش می‌کند و
  روی دستگاه می‌نویسد.
- **از URL** — دستگاه دانلودش می‌کند. مرورگر نمی‌تواند از این صفحه به آدرس
  دلخواه درخواست بزند (CORS)، پس این مسیر از `/api/net/fetch` روی فرمویر
  می‌گذرد که خودش TLS را انجام می‌دهد و بایت‌ها را برمی‌گرداند.
- **از رجیستری** — یک ایندکس JSON از بسته‌ها. رجیستری پیش‌فرض همراه فرمویر
  می‌آید؛ می‌توانید به رجیستری خودتان اشاره کنید.

## قالب رجیستری

```json
{
  "name": "Dsp32 Official",
  "updated": "2026-08-06",
  "apps": [
    {
      "id": "ir.dsp32.hello",
      "name": "Hello",
      "version": "1.0.0",
      "author": "Dsp32",
      "description": "اولین اپ Dsp32.",
      "size": 3200,
      "url": "https://example.com/apps/hello.dib",
      "sha256": "9f2c…"
    }
  ]
}
```

`sha256` اینجا کل فایل `.dib` را پوشش می‌دهد، پس فروشگاه می‌تواند دانلود را
قبل از باز کردن بررسی کند. هر میزبان استاتیکی کار می‌کند — یک آدرس raw از
گیت‌هاب، یک باکت S3، یا حتی فایلی روی کارت SD خود دستگاه.

## نوشتن یک اپ

```js
// main.js — رابط runtime را به‌عنوان App دریافت می‌کند
Dsp32.app(function (App) {
  const win = App.window({ title: 'Hello', w: 420, h: 300 });
  win.body.innerHTML = `
    <div style="padding:20px">
      <button class="btn primary" id="go">Read chip</button>
      <pre id="out"></pre>
    </div>`;

  win.body.querySelector('#go').onclick = async () => {
    const s = await App.system();                    // نیاز به "system"
    win.body.querySelector('#out').textContent = `${s.chip} @ ${s.cpuMhz} MHz`;
    await App.storage.set('lastChip', s.chip);       // نیاز به "storage"
    App.notify('Hello', 'اطلاعات چیپ خوانده شد');    // نیاز به "notify"
  };
});
```

`Dsp32.app(fn)` اپ را ثبت می‌کند؛ `fn` هر بار که اپ اجرا شود صدا زده می‌شود و
یک شیء `App` می‌گیرد که به مجوزهای مانیفست محدود شده است. صدا زدن متدی که
مانیفست اعلامش نکرده، خطا می‌دهد — پس مجوز فراموش‌شده موقع توسعه معلوم
می‌شود نه اینکه بی‌صدا کار نکند.

رابط کامل runtime:

| | |
|---|---|
| `App.window(opts)` | یک پنجره‌ی دسکتاپ باز می‌کند؛ همان شیئی که `WM.open` می‌دهد |
| `App.manifest` | مانیفست، همان‌طور که نصب شده |
| `App.dir` | پوشه‌ی اپ روی دستگاه |
| `App.asset(path)` | آدرس یک فایل داخل بسته |
| `App.storage.get/set/remove/all()` | فضای کلید/مقدار خصوصی |
| `App.fs.list/read/write/mkdir/delete()` | فایل‌سیستم دستگاه |
| `App.net.fetch(url, opts)` | درخواست HTTP(S) از طریق دستگاه |
| `App.notify(title, body)` | اعلان دسکتاپ |
| `App.system()` | اطلاعات دستگاه |
| `App.camera.snapshotUrl/save()` | دوربین |
| `App.bus.on/emit()` | پیام بین اپ‌های در حال اجرا |
